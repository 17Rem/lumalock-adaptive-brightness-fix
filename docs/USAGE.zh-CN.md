# LumaLock 使用说明

LumaLock 用于解决匹配型号的便携屏随画面内容缓慢变亮、变暗的问题。它把面板正在使用的亮度曲线替换为面板自带、已经核验的高亮度曲线；无需拆机，不刷固件。

## 1. 确认适用范围

目前只包含 BOE NE180QDM-NZ4（EDID：BOE0C64）与 Novatek NT71873 的一个已验证配置。程序会自动检查显示器身份、固件代码和两张原厂曲线。同款面板的序列号和生产日期可以不同，但固件或曲线不符时会停止。

仅有“2560×1600、240 Hz、500 尼特”等规格相同，不代表兼容。不需要手动输入研究时那块屏幕的编号，也没有强制跳过核验选项。

Windows NVIDIA 已实机验证。Windows AMD、Intel 和原生 Linux 已有实现与离线测试，仍属实验性支持。连接方式必须能访问目标面板的 DP/eDP AUX；显卡品牌、USB-C 接口外形或面板型号本身都不能保证通信成功。详情见[平台说明](BACKENDS.md)。

## 2. 准备环境

1. 安装 64 位 Python 3.10 或更新版本，并让 `py` 或 `python`（Linux 为 `python3`）命令可用。
2. 安装显卡驱动。Intel 另需官方 IGCL 的 `ControlLib.dll`，涉及 AUX 写入时需管理员权限。
3. 下载并解压完整项目，保持目录结构。无需安装 pip 依赖。
4. 接好便携屏，退出其他正在修改显示器参数的工具。操作期间保持连接和供电。

Windows 启动脚本会优先使用 `py -3`，否则使用 `python`。若系统安装了多个 Python，请确认选中的版本为 64 位且不低于 3.10。不要使用 `python -O` 或设置 `PYTHONOPTIMIZE`。

## 3. 查找屏幕并核验

在项目目录打开终端，Windows 运行：

```powershell
.\run.cmd list
.\run.cmd check
```

Linux 运行：

```sh
sh ./run.sh list
sh ./run.sh check
```

`list` 只表示初步识别到候选。`check` 会从屏幕读取数据，与项目中的兼容性摘要核对，确认当前曲线已知，并恢复临时查询状态；不会改写亮度曲线。它不是完全无写操作：查询窗口和 AUX 控制状态需要临时切换。

没有安装的显卡接口可能出现在列表中并附带错误原因；只要实际使用的接口正常即可。可指定接口减少无关信息：

```powershell
.\run.cmd check --backend nvidia
```

如果发现多块兼容候选，复制 `list` 输出的完整编号：

```powershell
.\run.cmd check --display "nvidia:0x12345678"
```

上面的编号只是示例。后续 `apply` 和 `restore` 使用同一个实际编号。Linux 编号可能含 `|`，必须保留引号。程序不会在恢复时自动换到另一块屏幕。

## 4. 固定高亮度

Windows：

```powershell
.\run.cmd apply
```

Linux：

```sh
sh ./run.sh apply
```

每次都会重新核验，不会依赖上一次 `check` 的结果。请等待完成，可能需要几分钟；不要同时开启第二次操作。成功后高亮度持续生效，没有观察测试的倒计时。已经是高值曲线时，不会重复写表。

该高值来自面板自身的原厂表，不是超频或超出原厂表的亮度数值，也不提供任意增亮参数。应用成功后可切换深色和浅色画面，观察同一固定区域是否还会缓慢变亮或变暗。

## 5. 恢复与重启

恢复原始自适应曲线：

```powershell
.\run.cmd restore
```

Linux 使用 `sh ./run.sh restore`。本工具只改易失内存；断电、休眠或重新连接后，设置可能失效，再运行 `apply` 即可。项目默认不会添加开机启动、计划任务或后台常驻服务。

运行中会启动独立恢复进程，最长操作期限为六分钟，正常结束后关闭。如果写入或校验失败，主进程会尝试恢复原始曲线和查询状态；若主进程异常退出，恢复进程在期限到达后尝试恢复。通信中断时不能保证恢复成功。

如果屏幕异常或恢复失败：不要连续重试，先停止其他显示器控制程序，等待恢复期限结束，再断开屏幕电源并重新连接。保留错误信息以供排查。

## 6. 备份、日志与隐私

默认保存位置：

| 系统 | 位置 |
| --- | --- |
| Windows | `%LOCALAPPDATA%\LumaLock` |
| Linux | `$XDG_STATE_HOME/lumalock`，未设置时为 `~/.local/state/lumalock` |

其中包含每台设备的原始 256 字节亮度表、恢复状态及诊断记录。**这不是完整固件备份，不能用于刷机或修复损坏的固件。** 发布源码没有附带固件或实际曲线，运行时从自己的屏幕读取并核验。

诊断记录可能包含 EDID、显示器编号、本机路径、原始固件读取片段等。提交公开问题时先提供报错文字、面板型号、系统、显卡和连接方式，不要直接上传整个日志目录。自定义 `LUMALOCK_STATE_DIR` 时也请使用源码目录以外的位置；用管理员权限运行可能改变日志归属和保存位置。

## 7. 常见情况

| 提示或现象 | 处理方式 |
| --- | --- |
| 没有兼容候选 | 检查实际面板型号、视频连接及显卡接口；先查看 `list` 的具体原因 |
| 固件摘要不匹配或读取不稳定 | 停止使用该配置，不修改摘要强行通过；记录型号、连接方式和错误 |
| 当前亮度曲线无法识别 | 退出其他控制程序，断电重连后重新 `check`；仍不符则暂不支持 |
| Linux 找不到 AUX/I²C 或权限不足 | 查看平台说明中的内核接口、配对和权限要求 |
| Intel 无法加载运行库 | 安装官方驱动与 IGCL，确认位数和权限 |
| 重启后又会自动调光 | 易失设置已重置，重新运行 `apply` |
| 屏幕已锁定但希望更亮 | 工具只提供已验证原厂高值，不提供未知亮度值写入 |

## 8. 开发与测试

```powershell
python -B -m unittest discover -s tests -v
```

测试使用合成数据，不连接显示器。覆盖设备匹配、不同显卡接口、曲线核验、部分写入失败、恢复及目标设备绑定。离线测试通过不等于 AMD、Intel 或 Linux 的实机兼容性已经验证。
